# Handoff 2026-11-17: browser wallet UI (chain-vaults step 6)

Branch `wallet-ui`, branched from `chain-vaults` at 2f03581. Only `web/`, `tasks/frontend.md` and this file changed.

## What was built
- Connect an injected EIP-1193 wallet (MetaMask etc.), detect the network, switch to Arc Testnet, and add the network if the wallet does not know it (4902). Add-chain values come from `GET /api/chain` (`rpc_url`, `explorer_url`, `chain_id`, `chain_name`). Native currency is USDC with 18 decimals, as Arc and viem's `arcTestnet` define it. Every displayed amount uses the ERC-20 `balanceOf` at `usdc_address` (6 decimals).
- Agent detail, "Arc testnet vault" section:
  - No vault: a "Create vault" form. Caps are prefilled from the agent policy. The owner signs `VaultFactory.createVault(operator_address, maxPerChallenge, maxExposure, agentRef)`. After the receipt, the page POSTs `/agents/{id}/vault {tx_hash}`. A "link by creation tx hash" form covers recovery.
  - Linked: vault address, owner ("you" when connected), operator, paused, caps, onchain balance and exposure, ledger available and committed, drift with an explanation, and explorer links.
  - Actions: Allocate (amount, or % of wallet with 25%/50%/Max presets) signs `USDC.transfer(vault, amount)`, then POSTs `/vault/sync`. Withdraw signs `withdraw(connected wallet, amount)`, then POSTs `/vault/sync`. Pause/unpause signs `setPaused`. Caps sign `setLimits`. Withdraw, pause and caps only show for the owner wallet.
  - "Sync a transaction by hash" form for transfers made outside the page.
  - Tx log: confirm in wallet, pending, confirmed, failed, rejected, then recording in ledger / recorded / not recorded (retry, no re-sign). Each row links to the explorer.
- Wallet page, "Arc testnet" section: connected wallet USDC, a per-agent vault table (in vault, staked, ledger available, drift, paused) and totals. These are never summed with simulated balances.
- Labels: "Arc testnet USDC (not real funds)" appears next to every onchain amount. The `arc_testnet` badge tooltip no longer says "Real".
- Ledger tables link `tx_hash` to the explorer for `arc_testnet` entries.

## How to run / test
- `cd web && npm ci && npm test && npm run lint && npm run build`
- Mock: `PORT=8099 npm run dev-mock` and `NEXT_PUBLIC_API_URL=http://localhost:8099/api npx next dev -p 3099`.
  - Env switches: `MOCK_CHAIN=disabled|missing`, `MOCK_OWNER=<your address>` (to see owner actions with a real wallet), `MOCK_SEED=0`.
  - Seeds three agents: one with a linked vault and drift, one simulated without a vault, and one answering 503 `chain_unavailable`. A link tx hash ending in `dead` returns 409 `agent_has_open_interactions`.
  - The mock never reads the chain. `/vault/sync` always credits nothing.
- Real backend: run as in AGENTS.md 9.4 with the chain settings. The web app needs no new env var.

## Assumptions about the backend contract (built exactly against the brief)
- `GET /chain` returns `{enabled:false}` or the full config. A 404 (older backend) is treated as disabled.
- `GET /agents/{id}/vault` returns 404 `vault_not_linked` (shows the create form) and 503 `chain_unavailable` (shows a retryable error).
- `drift` is signed and computed by the backend. The UI only displays it, with text "chain holds more" (positive) or "ledger shows more" (negative). **Please confirm the sign convention is onchain minus ledger.**
- `/vault` is POSTed only after the receipt is `success`. The backend can therefore assume the tx is mined.
- `/vault/sync` returns `credited: LedgerEntry[]`. A withdrawal shows up as negative deltas ("Debited ...").
- The agent's `env` flips to `arc_testnet` after linking. The page reloads the agent.

## Proposed decisions (for docs/decisions.md; not edited here)
- W-1: `viem` is the only wallet dependency. No wagmi or RainbowKit: one injected wallet and five contract calls don't need them. viem gives typed ABI encoding, revert decoding, receipts and an `arcTestnet` reference.
- W-2: Reads (USDC balance, receipts, pre-sign simulation) go through the backend-provided public RPC, not the wallet. Balances therefore load on the wrong network, and reverts (e.g. `NotOwner`) are explained before the owner signs.
- W-3: Fee floor. The tx is sent with `maxFeePerGas = max(estimate, 20 gwei)` on chain 5042002. Arc silently drops txs below 20 gwei.
- W-4: Allocate keeps 0.01 USDC in the wallet for gas, because Arc pays gas from the same USDC balance. % of wallet is exact bigint floor.
- W-5: The caps form only warns when max per challenge is greater than max exposure, or when either is 0. The contract allows both.
- W-6: Withdraw always goes to the connected owner wallet. There is no free "to" field.
- W-7: Only `window.ethereum` is detected. EIP-6963 multi-wallet discovery is not implemented.

## Verified
- Unit tests: 82 total, 34 new (`lib/chain`, `lib/wallet`, `lib/txlog`, `lib/vault`). Calldata was cross-checked against `cast calldata` / `cast sig`.
- Checked in Chrome against the mock, with a fake injected provider. No real tx was sent, because the fake wallet rejects `eth_sendTransaction`.
  - Connect; wrong network, then switch (the add-chain params were captured and checked).
  - Live Arc RPC USDC balance read; vault view and drift.
  - Validation: withdraw over balance, 100% allocation (gas reserve), bad caps, warning when the per-challenge cap exceeds exposure. 50% preview math.
  - Pause and createVault were simulated against the real Arc contracts. `eth_sendTransaction` carried the correct calldata (agentRef = agent UUID) and the fee floor. The wallet rejection showed "Rejected in wallet".
  - Link by hash: bad hash, 409, and success (the agent flips to arc_testnet and the tx log survives). Sync note.
  - States: 503, no wallet installed, chain disabled, `/chain` 404, backend unreachable.
